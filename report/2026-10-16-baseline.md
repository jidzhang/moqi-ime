## 全栈管线发现与修复（10-17 深夜）

**字母 release 被喂进引擎**：真实 C++ 宿主每键发 filterKeyUp/onKeyUp，
Go 的 filterKeyUp 把对拼音无语义的字母 release 也转发 dll，扰乱组句与

修复：release 只对 Shift/Caps 进引擎（中英切换依赖 up 语义），其余键
直接清状态（`isKeyReleaseRelevantForBackend`）。

**未结案**：全栈（修复后）45.2 vs 直连 55.3 仍有 ~10 点差。已排除：

**教训**：全栈跑分必须全新 user dir + user_dict ON + 单变量变更，
否则学习轨迹/部署状态漂移会让臂间差 ±3-6 点全是噪声。

  句尾词另有 `前缀$` 键；查询端值需 >e^8≈2981 才压过 non_collocation_penalty(-4)
  ——即训练值用原始词对计数，只有强搭配才改变排序。

## 2026-10-17 下午：两案结案 + 测评口径修复 + 套件 v1.1 两档制

## 2026-10-17 晚：算法迭代 #1 —— abbrev_sentences（组句门控），核心场景 +2.5

### 根因链（三步定位，全部有日志/探针实证）
1. 显微镜探针（probe-shin）发现：混合输入"shin"的首候选排序里语法模型从未参与——
   480 次 grammar 查询全是联想预测（ctx=已上屏词），组句路径零查询。
2. script_translator.cc 的组句门控：`has_reliable_phrase`（整段精确匹配词，如
   shin→十年、dern→第二年）存在时直接跳过组句——简拼边命中的紧凑词把
   poet+grammar 整个旁路。这是 d3 混合连打 essay 零增益、两词简拼被碾压、
   d6 崩盘的共同机制上游。
3. 注意：frost schema 默认带 `grammar/language: zh-moqi`（7MB 自训小 gram，
   为让 non_collocation_penalty=-4 生效），所以"无 gram 的 base 臂"其实也有
   grammar 对象——门控开关必须显式 opt-in 而不能依赖 grammar 是否存在。

### 改动（librime-gaboolic，全部配置驱动，默认零行为变化）
- `translator/abbrev_sentences: true`（新开关，默认 false）：混合输入
  （同时含全拼音节边与简拼边）时，即使存在整段精确匹配词也构建组句候选，
  让带语法模型的句子与词候选同台竞争。纯全拼、纯简拼输入行为不变。

  运行时可用 GLOG_minloglevel 过滤；发布版应降级为 DLOG。

## 2026-10-19（深夜二）：首切卡顿真根因闭环——Inno 亚秒丢失 + to_time_t 随机抖动，±2s 容差修复

### 一、现象与旧结论修正

用户两台机器重装后首切仍卡（thinkpad 14.3s / 本机 5.9s）。此前"旧包 checksum 失配"
只是表象的一层，真根因是**装机链路上时间戳精度丢失 + librime 读数随机抖动**的复合：

1. 打包时 normalizeYamlMtimes 把 yaml mtime 归一为"偶数整秒+0.5s"，预编译产物
   __build_info.timestamps 记录偶数值（如 1792408196）。
2. **Inno Setup 6.7.3 安装文件时丢弃亚秒精度**（本机实测：舞台 19:09:56.5 →
   装机后 19:09:56.0）。.5s 缓冲层在装机环节被剥掉。
3. librime `to_time_t`（algo/fs.h）= `tp - file_clock::now() + system_clock::now()`
   两次时钟读数换算 + `(int)` 截断。整秒 .0 的文件**每次读取随机读出 N-1 或 N**
   （证据：本机同一次部署，同一个 default.yaml 在 cangjie5/radical_pinyin/sogou
   产物里记 1792408195，其余产物记 1792408196）。
4. ConfigNeedsUpdate（deployment_tasks.cc）用精确 != 比较 → "源文件变了"判定变成
   **逐文件掷硬币**：每次装机随机重编若干 schema（本机 7 个 5.9s、thinkpad 8 个
   14.3s、旧 DLL 探针 18.1s 全量），次次不同。config 重编 → 编译产物 yaml 内容变
   （__build_info）→ schema_file_checksum 变 → prism 重编（melt_eng_t9 7MB ≈8s）。

### 二、修复

- **librime `ConfigNeedsUpdate` 加 ±2s 容差**（deployment_tasks.cc）：
  `drift = current - recorded`，|drift| > 2 才判 changed。真编辑的 mtime 差是分钟级，
  不会漏判；recorded=0（新增文件）仍能触发。日志带 `mtime drift Ns` 便于排查。
- **附带修复：HEAD 2bd5841b 编不过**——该提交给 ScriptTranslation 加了
  EvaluateWithGraph 定义与调用，但漏提交类声明一行（当时 05:30 编 DLL 的工作区是
  全的，05:36 提交后 18 小时无人重编所以没暴露）。已在 script_translator.cc 类内
  补 `bool EvaluateWithGraph(Dictionary*, UserDictionary*);` 声明。
- **安装器 StopMoqiProcesses 增杀 server.exe**（路径限定 PowerShell，只杀
  {app}\ 下的，防误杀同名进程）：孤儿后端不在启动器进程树里，不杀会锁 exe
  导致覆盖安装写不进新文件、且继续用旧代码服务。
- warmup 机制核对：启动器每次拉起后端立即发 warmup init/activate/keydown

### 四、日志门控真根因(trace 从未生效;纠 04 第九节的错误归因)

- `libIME2/src/DebugLogConfig.cpp:54` `parseDebugLogLevel`:先整份文本转小写,再

  `logTextServiceDebug`/`appendCandidateWindowLog` 全被门控,`tsf-debug.log`/
  `candidate-window.log` 永不生成。
- 与观察逐点吻合:同目录只有 tsf-dllmain-*.log(独立 logger,不门控)与
  Rime.MoqiIM.*.log.INFO/WARNING(spdlog,debug 档),即 **debug 有效、trace 无效**。
- 故 04 第九节"candidate-window.log 没生成 = 跑的是旧 DLL"的归因**不成立**;
  正确结论=门控解析顺序 bug。修法:配置只写 `{"logLevel":"trace"}`(launcher 会自夹到
  debug,前端小写化命中 trace),或把解析改成扫全部匹配取最高档。
  注意 PipeServer::saveConfig() 只回写 logLevel 一个键(托盘切档会丢键)。

### 二十、`4.` 直出：根因、Lua processor 方案、探针实测

- 用户报："我按了 4. 后光标停在 . 上面，还是学习微软拼音吧，直接打出 4. 就好了。"
- **根因（探针复现，非推断）**：`rime_frost.schema.yaml` 的
  `speller/alphabet` 只有字母 + `` ` `` + `/`，**没有数字**：
  1) 数字键进不了组字框，引擎也没有任何 punctuator 规则接数字 → 数字被丢弃；
  2) 紧跟的 `.` 被 punctuator 收进组字框 → 组字框只剩 `.`，光标停在它上面；
  3) 按空格才上屏，用户看到的是"4 没了、光标卡在 ."。
- 改动前探针（`eval-workspace/ime-type.exe`，全栈 Go 管线 + 真 VK 按键）：
  ```
  == "4."   composition="."   commit=". "            ← 4 丢失
  == "4.5"  composition=""    mid-key commits=[".5"]  ← 4 丢失
  == "12."  composition="."   commit=". "            ← 12 丢失
  == "."    mid-key commits=["。"]                   ← 单独句号正常
  ```
- 方案：新增 Rime Lua processor `moqi_plain_number.lua`
  （源文件 `input_methods/rime/patches/`，由 prebuild 拷进 `<data>/lua/`），
  挂在 frost 系 schema 的 `engine/processors` 里、**`ascii_composer` 之后**：
  - 组字框空且无候选时，数字键立即上屏（半角 0-9）；
  - 紧跟数字的 `.` 立即上屏半角点；
  - 组字中（有拼音 / 有候选窗口）一律不拦截，数字仍由 selector 选第 N 个候选；
  - 其它键清"上一键是数字"标记，标点仍走全角；Ctrl/Alt/Win 组合键不拦；
  - **T9 数字九宫格整套跳过**（字母表本就含数字，数字是输入不是直通）：
    打包期不往 t9 schema 挂 + Lua 侧读 `speller/alphabet` 自查，两道保险。
- 改动后探针（同一 stage 数据）：
  ```
  == "4."      mid-key commits=["4" "."]        ← 用户要的
  == "4.5"     mid-key commits=["4" "." "5"]
  == "12."     mid-key commits=["1" "2" "."]
  == "4"       mid-key commits=["4"]
  == "."       mid-key commits=["。"]            ← 单独句号不变
  == "nihao."  mid-key commits=["你好。"]        ← 汉字后点号仍全角
  == "nihao1"  mid-key commits=["你好"]          ← 组字中数字仍选候选
  == "nihao4"  mid-key commits=["拟好"]          ← 同上（选第 4 个）
  == "shi4."   mid-key commits=["事" "。"]       ← 选完候选后点号仍中文句号
  ```
- 打包期实现：`cmd/rime-prebuild/main.go` 新增 `installPlainNumberProcessor(dataDir)`
  （拷 lua + 在 `rime_frost*.schema.yaml` 的 `- ascii_composer` 之后插入
  `- lua_processor@*moqi_plain_number`；幂等：已挂载则跳过）。
